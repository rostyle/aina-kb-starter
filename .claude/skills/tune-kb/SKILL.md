# ナレッジベースの点検（自分の使い方に合わせて作り直す）

ナレッジベースは**作品ではなく設定**。持ち主の使い方が変われば合わなくなる。
このスキルは「散らかりを片付ける」（→ `organize`）ではなく、**`AGENTS.md` 側＝AIへの指示そのものを、今の使い方に合わせて直す**。

## 大原則

- **提案 → 承認 → 反映。** 勝手に `AGENTS.md` を書き換えない。必ず一覧で見せて、OKが出たものだけ反映する
- **思いつきでルールを増やさない。** 根拠は「回数」。実際に繰り返し起きたことだけをルールに昇格させる
- **足したら、減らす。** ルールは増やすほど効かなくなる。守られていない記述は、具体化するか消す

## 1. 材料を集める（探すのはAIの仕事）

直近1か月ぶんの `ログ/`・`受信箱/`・更新されたファイル、そしてこの会話でのやり取りを読み、次の4つを拾う。

| 拾うもの | 見つけ方 | 昇格先 |
|---|---|---|
| **毎回している前置きの説明** | 「私は◯◯の仕事で」「いつも◯◯なので」が繰り返し出てくる | `AGENTS.md` の「私について」／`自分/` |
| **何度も言い直させたこと** | 「そうじゃなくて」「もっと短く」「そこは違う」の直後の指示内容 | `AGENTS.md` の「書き方の好み」／役割／「自分で判断してよい範囲」 |
| **守られていない記述** | `AGENTS.md` に書いてあるが、実際の会話で1度も効いていないもの | 具体化 or 削除 |
| **二重管理** | 同じ内容が2か所以上のファイルにある | どちらか1つに寄せる（真実源は1つ） |

**2回以下のものは「様子見」として出すだけ。3回以上出たものを「ルール化を推奨」とする。**
あわせて、3回以上繰り返している作業があれば「スキル化の候補」として出す（`.claude/skills/` に新設）。

## 2. 提案を一覧で出す

```
【ルールに昇格させたい】3回以上出たもの
1. ○○ → AGENTS.md の「書き方の好み」に1行で追加：「〜する」

【消す・具体化する候補】守られていない記述
2. 「丁寧に書く」→ 曖昧。具体化案：「敬語は使うが、前置きは書かない」

【二重管理】
3. 人物/山田太郎.md と 仕事/A社/README.md に同じ経緯 → 人物/ に寄せる

【スキル化の候補】
4. 毎週やっている「◯◯の集計」→ .claude/skills/◯◯/SKILL.md
```

判断は持ち主に返す。**「どれを反映しますか（番号で）」で終える。**

## 3. 反映する

- ルールは **1文に1ルール**。「〜しない」より「〜する」で書く
- `AGENTS.md` は要点だけ。中身が厚くなったら `自分/` へ分けてリンクにする
- `CLAUDE.md` は触らない（`AGENTS.md` を読み込む1行のまま）
- 反映したら読み戻し、**何をどう変えたかを3行以内で報告する**

## 4. 効き目を測る（3か月に1回、または大きく直したとき）

持ち主に、こう提案する：

> 「私について今わかっていることだけを踏まえて、私の代わりに◯◯を書いて。そのあと、これを書くのに足りなかった情報を教えて」——これを打ってみてください。

出てきた**「足りなかった情報」が、次に埋める場所**。当てずっぽうで足さない。

## やらないこと

- 承認なしに `AGENTS.md` を書き換える
- 1回しか起きていないことをルールにする
- ルールを足すだけで、減らさない
- 曖昧な言葉（「丁寧に」「適切に」「しっかり」）でルールを書く
