# 持ち場とカルテ（AIに前回の続きを覚えさせる）

役割は `README.md`、今の状態は `カルテ.md`。2つを分けるから、次に開いたときに前回の仮説から続けられる。
**型は `仕事/README.md` に書いてある。** 作る前に必ず読む（ここには型を複製しない）。

## 1. 持ち場を立てるとき

聞くのは3つだけ。1問ずつ。

1. 何のための持ち場か（ゴール。数字か○×で判定できる形に言い換えて確認する）
2. やらないこと（境界）
3. 見る数字（3つまで。無ければ「観測経路なし」と書いてよい）

- `仕事/{持ち場}/README.md` と `カルテ.md` を型どおりに作る。フォルダ名は持ち主の言葉のまま（日本語でよい）
- 関係者が出たら `人物/` を確認し、無ければ `person-log` を提案する。人の詳細を README に書かない
- `稼働`（週次／月次）と `次のチェック日` を決める。迷ったら週次・7日後
- 打ち手が出ていれば `todo.md` に T番号で置き、カルテからは番号で参照する
- 2ファイルを読み戻して、パスと次のチェック日を1〜2行で報告する

## 2. カルテを更新するとき（触るたび）

この順番で。**飛ばさない。**

1. **見る数字**：現在値・前回・取得日を更新。出典なしで書かない。前回が無ければ「初回」
2. **今の仮説**：なぜその数字か。1〜3行。前回と変わらなければ「変わらず」と書いてよい
3. **実行中の打ち手**：誰が・いつまでに・何を。3点欠けたら打ち手と呼ばない。`todo.md` と番号を揃える
4. **前回のCheck**：前回こう予測した → 実際どうだった → 差分をどう解釈するか。**ここが中核。** 前回の予測が無ければ、今回の予測を1行書いて次回に備える
5. **判断ログ**：迷って決めたこと・見送ったことと理由

- 「異常なし」は書かない。出すのは差分と滞留だけ
- 動く線（閾値）を割っていたら、書いてある IF→THEN を実行するか、実行しない理由を判断ログに書く
- 打ち手が空のまま2回続いたら `稼働: 休眠` を提案する
- `次のチェック日` を進めるのは、実際に数字を見たときだけ

## 3. 持ち場を終えるとき

- ゴール到達か中止か、どちらかを判断ログに1行書く
- フォルダごと `仕事/archive/` へ移す。`todo.md` の関連 T番号を完了にする
- 人物ファイルは動かさない（`status` を変えるだけ）

## やらないこと

- README に今の数字を書く／カルテに役割を書く
- 日付だけ更新して、実測したように見せる
- 数字を推測で埋める（取れないものは「観測経路なし」）
- 持ち主が言っていない打ち手を勝手に T番号にする（提案は P番号）
