# 片付ける・棚卸しする

ナレッジベースが死ぬ原因は、情報が少ないことではなく**散らかって信用できなくなること**。定期的に整える。

## 週1回：受信箱を空にする（5分）

### 1. `受信箱/` の中身を全部読む

### 2. 1件ずつ、4つのどれかに決める

| 判定 | 行き先 |
|---|---|
| 使える情報 | 適切なフォルダへ移す（`置き場所ルール` に従う） |
| **既にある情報** | 既存ファイルに**統合**して、受信箱の方を消す |
| もう要らない | 消す |
| まだ決められない | 残す。**ただし3週間残り続けたものは消す**（判断できないものは、たいてい要らない） |

### 3. 迷ったら本人に聞く

判断がつかないものは、**まとめて1回だけ**聞く。1件ずつ確認を取らない（面倒になって続かなくなる）。

### 4. 終わったら報告する

「受信箱 12件 → 0件。◯◯を仕事/へ、△△を人物/へ、5件を削除しました」と3行で。

## 月1回：棚卸し（10分）

### 1. 終わったものを archive へ

- 完了した案件、関係が終わった人、古くなった資料
- **消さずに `archive/` サブフォルダへ移す**（例：`仕事/archive/`）
- 人物ファイルは**動かさない**。`status: archive` に変えるだけ

### 2. 重複を潰す

- 同じことが2か所に書かれていないか探す
- 見つけたら**片方を真実源に決めて、もう片方はリンクに置き換える**
- **人の情報が `人物/` 以外に書かれていたら、必ず `人物/` へ寄せる**

### 3. 古い情報に印をつける

事実と違うかもしれない記述には、消さずに追記する：

> （2026-07-23 時点では未確認）

### 4. 気づいたことを3つだけ報告する

- 放置されているもの（例：受信箱に3週間残っている件）
- 書きかけで止まっているファイル
- **記録から見える傾向**（例：同じ相手の名前が今月8回出ている＝関係が濃くなっている）

長い分析はしない。**3つまで。**

---

## やらないこと

- 良かれと思って大量にファイルを移動・改名する（本人が自分のKBを見失う）
- 本人が書いた文章を勝手に書き直す（**整えるのは置き場所であって、中身ではない**）
- 消す前の確認を省く（**削除は必ず件数と内容を報告してから**）
