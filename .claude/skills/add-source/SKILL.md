# 素材を取り込む

外から来た情報を、**原文を残しつつ、使える形に変えて**ナレッジベースに入れる。

## 大原則：原文と、まとめは分ける

| | どこへ | なぜ |
|---|---|---|
| **原文**（記事全文・文字起こし・議事録の生ログ） | `素材/` | あとで元を確認できるようにする。ここは加工しない |
| **まとめ**（要点・自分への示唆） | `資料/` `仕事/` `人物/` など内容に応じて | 実際に使うのはこっち |

原文をいきなり要約して捨てない。**あとで「本当にそう言っていたか」を確認できることが、信頼できるナレッジベースの条件。**

## やり方

### 1. 素材の種類を見る

| 来たもの | どうする |
|---|---|
| URL | 中身を読む。読めない場合は本人に本文を貼ってもらう |
| 貼り付けテキスト・文字起こし | そのまま原文として扱う |
| ファイル（PDF・画像） | 中身を読み取る。**原本は `.gitignore` の対象になっていないか確認**（機密なら取り込まない） |

### 2. 原文を保存する

`素材/YYYY-MM-DD_{何の素材か}.md` として保存する。冒頭に出どころと秘密度を書く。

```markdown
---
source: https://example.com/article
type: 記事          # 記事 / 動画 / 打ち合わせ / 講座 / 本 / 自分の文章
date: 2026-07-23
visibility: L2      # 人の発言・お金・契約が入っていれば L3。公開記事は L0
---

（ここに原文）
```

### 3. 要点を抜く

**丸ごと要約しない。** この持ち主にとって意味がある部分だけを抜く。`AGENTS.md` の「私について」（特に目標）を読んでから判断する。

抜くのは3つ：

1. **事実** — 何が書いてあったか（1〜5行）
2. **自分への示唆** — 自分の仕事・目標にどう効くか
3. **すぐやれること** — あるなら1つだけ（やるなら `todo.md` に T番号で。提案止まりなら P番号で）

引用は【逐語】（原文ママ）と【要約】（編集した引用）を分けて書く。

### 4. 置き場所を決める

| 内容 | どこへ |
|---|---|
| 仕事に直結する情報 | 該当する `仕事/{持ち場}/` の README（役割が変わる話）か カルテ（数字・仮説が変わる話）に追記 |
| 人についての情報 | `人物/{名前}.md` へ（`person-log` の手順に従う） |
| 考え方・学び | `資料/学び_{テーマ}.md` にまとめて蓄積 |
| どこにも当てはまらない | `受信箱/` に置いて、次の `organize` で判断 |

### 5. 報告する

「素材/◯◯ に原文、資料/◯◯ に要点3つ」のように、どこに何を書いたかを2〜3行で。

## やらないこと

- 原文を捨てて要約だけ残す
- 有料コンテンツや他人の著作物を丸ごと置く（要点と出どころに留める）
- 出どころ不明のまま入れる
- 持ち主に関係ない部分まで律儀に要約する
