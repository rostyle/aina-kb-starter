# 素材を取り込む

外から来た情報を、**原文を残しつつ、使える形に変えて**ナレッジベースに入れる。

## 大原則：原文と、まとめは分ける

| | どこへ | なぜ |
|---|---|---|
| **原文**（記事全文・文字起こし・議事録の生ログ） | `素材/` | あとで元を確認できるようにする。ここは加工しない |
| **まとめ**（要点・自分への示唆） | `資料/` `仕事/` `人物/` など内容に応じて | 実際に使うのはこっち |

原文をいきなり要約して捨てない。**あとで「本当にそう言っていたか」を確認できることが、信頼できるナレッジベースの条件。**

## やり方

### 1. 素材の種類を見る

| 来たもの | どうする |
|---|---|
| URL | 中身を読む。読めない場合は本人に本文を貼ってもらう |
| 貼り付けテキスト・文字起こし | そのまま原文として扱う |
| ファイル（PDF・画像） | 中身を読み取る。**原本は `.gitignore` の対象になっていないか確認**（機密なら取り込まない） |

### 2. 原文を保存する

`素材/YYYY-MM-DD_{何の素材か}.md` として保存する。冒頭に出どころを書く。

```markdown
---
source: https://example.com/article
type: 記事          # 記事 / 動画 / 打ち合わせ / 講座 / 本
date: 2026-07-23
---

（ここに原文）
```

### 3. 要点を抜く

**丸ごと要約しない。** この持ち主にとって意味がある部分だけを抜く。`CLAUDE.md` の「私について」を読んでから判断する。

抜くのは3つ：

1. **事実** — 何が書いてあったか（1〜5行）
2. **自分への示唆** — 自分の仕事・目標にどう効くか
3. **すぐやれること** — あるなら1つだけ

### 4. 置き場所を決める

| 内容 | どこへ |
|---|---|
| 仕事に直結する情報 | `仕事/` の該当ファイルに追記 |
| 人についての情報 | `人物/{名前}.md` へ（`person-log` の手順に従う） |
| 考え方・学び | `資料/学び_{テーマ}.md` にまとめて蓄積 |
| どこにも当てはまらない | `受信箱/` に置いて、次の `organize` で判断 |

**既に同じテーマのファイルがないか、先に探す。** あれば新規作成せず追記する。

### 5. リンクでつなぐ

まとめの側に、原文へのリンクを必ず書く。

```markdown
出どころ: [素材/2026-07-23_○○の記事](../素材/2026-07-23_○○の記事.md)
```

### 6. 保存する

何をどこに入れたかを3行で報告してから、コミットして Pull request を上げる。

## やらないこと

- 原文を保存せずに要約だけ残す（あとで検証できなくなる）
- 出どころ不明のまま取り込む（必ず source を書く）
- 有料コンテンツ・他人の著作物を丸ごとコピーして保存する（要点と出どころに留める）
