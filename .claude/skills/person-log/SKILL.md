# 人物ファイルを育てる

**人の情報は `人物/{名前}.md` にだけ置く。** 他の場所にプロフィールを作らない（真実源は1つ）。

## やり方

### 1. 誰の話かを特定する

- `人物/` を検索して、**既存ファイルがあるか必ず先に確認**する
- 表記ゆれ（山田／やまだ／Yamadaさん）に注意。同じ人のファイルを2つ作らない
- 初めて出てくる人なら、**まず書くべき人かを判断**する（下の基準）

### 2. 書く人 / 書かない人

| 書く | 書かない |
|---|---|
| ちゃんと話したことがある（打ち合わせ・1on1・長い会話） | 名刺交換しただけ |
| これから継続的に関わる（顧客・同僚・取引先・仲間） | 一度きりの問い合わせ |
| 自分の判断に影響する人 | 名前が出ただけの人 |

迷ったら書かない。**人数を増やすほど、手入れが追いつかなくなって全部が古くなる。**

### 3. ファイルの形

```markdown
---
name: 山田 太郎
relation: [顧客]          # 顧客 / 同僚 / 取引先 / 仲間 / 友人 / 家族 / 見込み（複数可）
status: active            # active / watching / archive
met: 2026-07-23
introducer: 佐藤          # いれば
---

## 基本
- 会社・肩書き／拠点／連絡手段

## 人柄・進め方
- 話し方、決め方の癖、こだわり、機嫌よく進む条件
- 触れないほうがいい話題

## 関心・課題
- 今その人が困っていること・やりたいこと

## 接点の記録
- 2026-07-23 ◯◯の件で打ち合わせ。△△を持ち帰り（[素材/2026-07-23_打ち合わせ](../素材/2026-07-23_打ち合わせ.md)）
```

### 4. 書く内容の基準

**「調べれば分かること」ではなく「接した自分にしか分からないこと」を書く。**

| 書く価値がある | 価値が薄い |
|---|---|
| 結論から話すと機嫌がいい | 会社の設立年 |
| 値段の話を先にすると引く | 公開されている経歴 |
| 前回「来期に検討」と言っていた | ネットに出ている情報 |

### 5. 更新するときのルール

- **上書きせず、追記する。** 前の記述と食い違ったら、古い方を消さずに「（2026-07-23時点では〜に変わった）」と併記する
- 「接点の記録」は**日付順に足していく**。1回1〜2行
- 関係が終わったら `status: archive` に変える（**ファイルは消さない・動かさない**）

### 6. 扱いに注意すること

- **本人が話した範囲を超えて書かない。** 憶測の人物評を書かない
- 住所・電話番号・家族構成などの個人情報は書かない
- 悪口を書かない。**そのまま本人に見られても困らない書き方**にする（実際、事故は起きる）

### 7. 保存する

誰のファイルをどう更新したかを報告してから、コミットして Pull request を上げる。
