# 人物ファイルを育てる

**人の情報は `人物/{名前}.md` にだけ置く。** 他の場所にプロフィールを作らない（真実源は1つ）。

## やり方

### 1. 誰の話かを特定する

- `人物/` を検索して、**既存ファイルがあるか必ず先に確認**する
- 表記ゆれ（山田／やまだ／Yamadaさん）に注意。同じ人のファイルを2つ作らない
- **同名の別人を疑う。** 会社名・関係・紹介者が一致するかを見てから同一人物と判断する
- 初めて出てくる人なら、**まず書くべき人かを判断**する（下の基準）

### 2. 書く人 / 書かない人

| 書く | 書かない |
|---|---|
| ちゃんと話したことがある（打ち合わせ・1on1・長い会話） | 名刺交換しただけ |
| これから継続的に関わる（顧客・同僚・取引先・仲間） | 一度きりの問い合わせ |
| 自分の判断に影響する人 | 名前が出ただけの人 |

迷ったら書かない。**人数を増やすほど、手入れが追いつかなくなって全部が古くなる。**

### 3. ファイルの形

```markdown
---
name: 山田 太郎
relation: [顧客]          # 顧客 / 同僚 / 取引先 / 仲間 / 友人 / 家族 / 見込み（複数可）
status: active            # active / watching / archive
met: 2026-07-23
introducer: 佐藤          # いれば
visibility: L3            # 人物は必ず L3
---

## 基本
- 会社・肩書き／拠点／連絡手段（連絡先そのものは書かない）

## 人柄・進め方
- 話し方、決め方の癖、こだわり、機嫌よく進む条件
- 触れないほうがいい話題

## 関心・課題
- 今その人が困っていること・やりたいこと

## 接点の記録
- 2026-07-23 ◯◯の件で打ち合わせ。△△を持ち帰り（[素材/2026-07-23_打ち合わせ](../素材/2026-07-23_打ち合わせ.md)）
```

### 4. 書く内容の基準

**「調べれば分かること」ではなく「接した自分にしか分からないこと」を書く。**

| 書く価値がある | 価値が薄い |
|---|---|
| 結論から話すと機嫌がいい | 会社の設立年 |
| 値段の話を先にすると引く | 公開されている経歴 |
| 前回「来期に検討」と言っていた | 肩書きの羅列 |

その人と交わした約束・頼まれたことは `todo.md` に T番号で置き、人物ファイルからは番号で参照する。

### 5. 保存して報告する

読み戻してから、「人物/山田太郎.md を更新（接点1件・関心1件追加）」のように1〜2行で報告する。

## やらないこと

- 悪口・評価を書く（本人に見られても困らない書き方にする）
- 住所・電話番号・家族構成などの個人情報を書く
- 仕事の進捗を人物ファイルに書く（それは `仕事/` とカルテ。人物からはリンク）
- 確認せずに新規ファイルを作る
