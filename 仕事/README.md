# 仕事（持ち場ごとに README と カルテ）

**今やっている仕事を「持ち場」の単位で置く場所。** 案件・役割・事業・続けたい習慣、どれでも持ち場になります。
ここが埋まると、AIが実務の相談相手になり、**次に開いたときも前回の続きを覚えています。**

## 2つのファイルに分ける（ここが一番大事）

| ファイル | 中身 | 変わる頻度 |
|---|---|---|
| `README.md` | **役割**：何をする持ち場か・やらないこと・ゴール（完了の定義）・関係者・AIに任せる範囲 | 変わったときだけ |
| `カルテ.md` | **今の状態**：見る数字・今の仮説・実行中の打ち手・前回のCheck・判断ログ | 触るたび |

**READMEに今の数字を書かない。カルテに役割を書かない。** これを守る限り、二重管理は起きません。
役割と状態を混ぜると、AIは毎回ゼロから分析して同じ提案を繰り返します。分けておくと「前回こう予測して、実際こうだった」から続けられます。

## 作りかた

AIに「◯◯の持ち場を立てて」と言えば、下の型で2つのファイルを作ります（`karte` スキル）。聞かれるのは3つだけ：①何のための持ち場か ②やらないこと ③見る数字（無ければ「観測経路なし」でよい）。

```
仕事/
  ネットショップ/        ← 持ち場（フォルダ名は日本語でよい）
    README.md
    カルテ.md
  archive/               ← 終わった持ち場はフォルダごとここへ
```

## README の型

```markdown
---
持ち場: 仕事/ネットショップ
種類: 事業            # 案件 / 役割 / 事業 / 習慣
関係者: [山田太郎]    # 人物/ の名前。人の詳細はここに書かない
visibility: L2
---

# ネットショップ — README（役割）

- **何をする持ち場か**：（1行）
- **やらないこと**：（境界。ここを書くとAIが暴走しない）
- **ゴール（完了の定義）**：（数字か、○×で判定できる形）
- **入力と出力**：（どこから情報が来て、何を出すか）
- **AIに任せる範囲**：（聞かずにやってよいこと／先に聞くこと。AGENTS.md の共通ルールに加える固有分だけ）
```

## カルテの型（5章。順序を変えない）

```markdown
---
持ち場: 仕事/ネットショップ
稼働: 週次            # 週次 / 月次 / 休眠
次のチェック日: 2026-10-01
visibility: L2
---

# ネットショップ — カルテ（今の状態）

## 1. 見る数字（3つまで・出典と取得日を必ず）

| 数字 | 現在値 | 前回 | 動く線（割ったら動く） | 出典 | 取得日 |
|---|---|---|---|---|---|
| 月の売上 | 42万円 | 38万円 | 30万円を2か月連続で下回る | 管理画面 | 2026-09-19 |

- IF 動く線を割ったら → THEN（判断を待たずにやること）

## 2. 今の仮説（なぜその数字になっているか。1〜3行）

## 3. 実行中の打ち手（誰が・いつまでに・何を。todo.md の T番号を付ける）

## 4. 前回のCheck（前回こう予測した → 実際どうだった → 差分の解釈）

## 5. 判断ログ（迷って決めたこと・見送ったことと理由）
```

- 「異常なし」は書かない。書くのは差分と滞留だけ
- 数字を出典なしで書かない。前回値が無ければ「初回」
- 打ち手が空のまま2回続いたら、その持ち場は `稼働: 休眠` にする（動いていないものを動いているように見せない）
- `次のチェック日` を過ぎたものは `weekly-review` が拾う。**日付だけ進めて点検したように見せない**

## 人の情報は、ここに書かない

顧客・同僚・取引先のプロフィールは **`人物/` に集約**します。ここからはリンクで参照してください。

```markdown
- 担当: [山田太郎](../../人物/山田太郎.md)
```

## ヒント

**「よくやる作業」を書き溜めるのが、いちばん効きます。**
3回以上やった作業は、`.claude/skills/` に自分専用の手順書として置くと、毎回説明しなくて済みます（「これをスキルにして」）。
会社で使う場合は、持ち場が部署になります。フォルダの形は変わりません。
