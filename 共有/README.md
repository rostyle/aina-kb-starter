# 共有（仲間や会社と一緒に使うプロジェクトの置き場）

ナレッジベースは2層で考えます。

| 層 | 場所 | 誰が読むか |
|---|---|---|
| **自分のナレッジベース** | このフォルダ全体 | 自分と、自分のAIだけ |
| **共有プロジェクト** | `共有/{プロジェクト名}/` | チーム・仲間・会社と、それぞれのAI |

共有プロジェクトは、**それ自体が別のリポジトリ**（別のフォルダの単位）です。ここには置き場だけを用意しておき、中身はそのプロジェクトのルールで管理します。
自分のナレッジベースが共有側を読めるので、「あの件どうなってた？」に自分のAIが答えられます。**共有側に書くと、報告が要らなくなります。**

## 使いかた（必要になったら）

1. プロジェクトの管理者から、リポジトリの場所（URL）をもらう
2. AIにこう頼む：「共有/ の中に、このリポジトリを置いて」（URL を貼る）
3. 以後、そのプロジェクトの作業は `共有/{プロジェクト名}/` の中の `AGENTS.md` のルールに従う

## ルール

- **この中は別のリポジトリ。** 自分のナレッジベースのバックアップには含めない（`.gitignore` で除外済み）
- 共有側へ出すファイルは、**`visibility` が L0 か L1 のものだけ**。人物ファイル・お金・契約（L3）は出さない
- 共有側に書いたことを、自分側にコピーしない。必要ならリンクで参照する（真実源は1つ）
- 共有側のルール（そのリポジトリの `AGENTS.md`）と自分側のルールが食い違ったら、**その中ではそのプロジェクトのルールが優先**

最初の1〜2週間は使いません。チームで何かを作り始めるときに読み返してください。
